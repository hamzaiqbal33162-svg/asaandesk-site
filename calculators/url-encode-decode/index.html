What URL encode and decode means

URL encode and decode is the way text is made safe to put inside a web address and turned back again. A link may only use a small set of characters, and some of them, such as ? & = / # and the space, have special jobs in the address. URL encoding, also called percent-encoding, writes every other character as % followed by two hex digits, so a space becomes %20 and & becomes %26. Decoding reverses it.

Without encoding, text can break a link. A search for "tea & cake" placed straight into ?q=tea & cake would look like two separate settings to the server. Encoded as tea%20%26%20cake, it arrives as one value, exactly as typed.

How to use the URL encoder and decoder

  • Choose Encode or Decode.
  • Encode: type or paste the text and pick what it is for in "Encode for": A value in a link (spaces as %20), Form data (spaces as +), Strict RFC 3986 (also ! ' ( ) *), or A whole web address (keeps : / ? # & =).
  • Decode: paste text with %-codes. Tick "Read + as a space (form data)" if the text came from a form or a query string that uses + for spaces.
  • Under More options, "Ignore spaces and line breaks at the start and end" is on by default; untick it to keep them.
  • Copy the result with the Copy button. The rows show the characters in, the characters out and how many %-codes were written or decoded.

If a code is broken, the result says exactly where, such as a % without two hex digits after it, or bytes that do not form valid UTF-8 text. Nothing you type is sent anywhere or saved in the page address.

URL encode rules: which characters change

RFC 3986 calls letters, digits and - . _ ~ "unreserved": they never need encoding. Characters with a job in the address (: / ? # [ ] @ ! $ & ' ( ) * + , ; =) are "reserved" and are encoded when they are part of a value. Everything else, including the space and every non-English character, is encoded as its UTF-8 bytes.

A whole address: https://example.com/search?q=tea & cake&city=Multan encoded as "A whole web address" becomes https://example.com/search?q=tea%20&%20cake&city=Multan. The & inside "tea & cake" is kept, so the server would read the search as just "tea ". Encode the value on its own first (tea%20%26%20cake) and then put it into the address.

Decoding: city%3DMultan%26note%3D50%25+off decodes to city=Multan&note=50%+off, and with "Read + as a space" ticked to city=Multan&note=50% off.

Common mistakes

  • Encoding twice: encoding text that is already encoded turns %20 into %2520. Decode first if you are not sure, then encode once.
  • Using + for spaces in the path: + means a space only in form data and many query strings; in the path of an address it is a real plus sign. Use %20 there.
  • A lone % sign: 100% is not valid in an encoded value; write 100%25. The decoder points to the exact character when a code is incomplete.
  • Mixing character sets: modern addresses use UTF-8. Old pages that used another set may decode to odd characters; for raw bytes in other sets, our Base64 Encode / Decode page can show them in hex.
  • Encoding the whole link as a value: "A value in a link" also encodes : and /, which is right for a link passed inside another link (?url=...) but breaks a link you want to open. Use "A whole web address" for that.

How it works

Web addresses may only contain a small set of characters, and some of them (& = ? / # and the space) have special jobs. Percent-encoding writes every other character as its UTF-8 bytes, each as % followed by two hex digits: a space is %20, é is %C3%A9. Choose what you are encoding: a value inside a link (the usual choice, the same as JavaScript's encodeURIComponent), form data as browsers send it (spaces become +), strict RFC 3986 (also encodes ! ' ( ) *), or a whole web address (keeps the : / ? # & = that separate its parts). Decoding turns the %-codes back into text and, if you tick it, + into spaces. Spaces at the start and end are left out unless you change that under More options.

The formula

  • Each character -> its UTF-8 bytes -> %XX for each byte (XX = the byte in hex, upper case)
  • space = %20 (or + in form data), & = %26, = = %3D, / = %2F, ? = %3F, % = %25
  • é = U+00E9 = bytes C3 A9 = %C3%A9; ☕ = U+2615 = E2 98 95 = %E2%98%95

A worked example

"a b&c=d/é?" as a value: a, b, c and d stay; the space is %20, & is %26, = is %3D, / is %2F, é is %C3%A9 and ? is %3F, so it becomes a%20b%26c%3Dd%2F%C3%A9%3F. As form data the space would be + instead.

Questions

What is URL encode?

URL encoding, or percent-encoding, writes characters that are not allowed or have a special job in a web address as % and two hex digits. A space becomes %20, & becomes %26 and é becomes %C3%A9. URL decode turns those codes back into the original text.

What are the URL encode rules?

Letters, digits and - . _ ~ stay as they are. Characters with a job in the address, such as & = ? / #, are encoded when they are part of a value, and every other character is written as its UTF-8 bytes in %XX form. Form data also writes spaces as +.

How do I URL encode and decode in JavaScript?

Use encodeURIComponent(text) for a value and decodeURIComponent(s) to decode. encodeURI(address) is for a whole address and keeps & = ? and /. URLSearchParams writes form data with + for spaces.

How do I URL encode and decode in Python?

Use urllib.parse.quote(text, safe='') for %20-style encoding or quote_plus(text) for form data with +, and unquote or unquote_plus to decode. Without safe='', quote leaves / unencoded.

How do I URL encode and decode in PHP?

rawurlencode follows RFC 3986 and writes spaces as %20; urlencode follows form encoding and writes spaces as +. Decode with rawurldecode or urldecode to match.

Should a space be %20 or +?

%20 is right everywhere in a web address. The + for a space only means a space in form data and in the query part of some servers' links (after the ?). If you are not sure, use %20; when decoding form data, tick "Read + as a space".

Why are / and : encoded when I paste a whole link?

"A value in a link" encodes everything that could change the meaning of a link, which is right when the text is one value inside another link (for example a link passed in ?url=). To tidy up a complete address and keep its parts working, choose "A whole web address".

What does "not a complete code" mean?

Every % must be followed by two hex digits (0-9 and A-F). A lone % or a code cut short, such as %E0%A4%A, cannot be decoded. A real percent sign is written %25, so 50% becomes 50%25.

Does it work for Urdu, Arabic and emoji?

Yes. Characters are written as their UTF-8 bytes, the standard for web addresses: é becomes %C3%A9, ☕ becomes %E2%98%95, a letter of the Urdu or Arabic alphabet becomes two codes such as %D8%B3, and everything decodes back exactly.

Is my text sent anywhere?

No. Encoding and decoding run in your browser, and the text boxes are not copied into this page's address, so links with private tokens do not end up in your history.
