How it works

Base64 writes any data with just 64 safe characters (A-Z, a-z, 0-9, + and /), so it can travel through email, web addresses, JSON and other places that only take plain text. To encode, your text is first turned into bytes, using UTF-8 unless you choose another character set, and every 3 bytes become 4 Base64 characters; = signs fill up the last group. To decode, the 4-character groups are turned back into bytes and the bytes are read as text. Spaces and line breaks in pasted Base64 are ignored, URL-safe Base64 (with - and _) and missing = signs are understood, and a data: prefix is skipped. Everything happens in your browser.

The formula

  • 3 bytes = 24 bits = 4 groups of 6 bits; each 6-bit group (0-63) is one character
  • 0-25 = A-Z, 26-51 = a-z, 52-61 = 0-9, 62 = + (or -), 63 = / (or _)
  • Base64 length = 4 × ⌈bytes ÷ 3⌉ with padding (1 or 2 = at the end), or ⌈4 × bytes ÷ 3⌉ without

A worked example

"Hi!" is the bytes 72, 105, 33 = 01001000 01101001 00100001. Split into 6-bit groups: 010010 000110 100100 100001 = 18, 6, 36, 33 = S, G, k, h, so "Hi!" is SGkh. "café ☕" is 9 bytes in UTF-8 and becomes Y2Fmw6kg4piV.

Questions

Is Base64 encryption?

No. Base64 only rewrites data with a small set of characters; anyone can decode it in a second, as this page shows. Never use it to hide passwords or private data. Use real encryption for that.

Why does my decoded text show odd characters such as � or Ã©?

The bytes were written in a different character set from the one used to read them, or the data is not text at all (an image or a zip file, for example). Under More options choose another "Read the bytes as" set, such as Windows-1252 for old Western files, or choose "Hex bytes" to see the raw bytes.

What is URL-safe Base64?

A variant that uses - and _ instead of + and /, because + and / have special meanings in web addresses and file names. It is often written without the = padding. JSON Web Tokens use it. This page decodes both kinds automatically; choose the alphabet under More options when encoding.

Why is the Base64 longer than my text?

Every 3 bytes become 4 characters, so Base64 is about 33% longer than the data. Letters outside English take 2 to 4 bytes each in UTF-8, so text in Urdu, Arabic or with emoji grows more.

Is my text sent anywhere?

No. The encoding and decoding run in your browser, and the text boxes are not copied into the page address, so a decoded secret does not end up in your history or in a shared link.
