What Base64 encode and decode means

Base64 encode and decode is a way to write any data, text or binary, using only 64 plain characters: the capital letters A to Z, the small letters a to z, the digits 0 to 9, and two extra signs, + and /. Encoding turns your data into that safe text. Decoding turns the text back into the exact same bytes.

It exists because many systems were built to carry text, not raw bytes. Email, web addresses, JSON files, XML and HTTP headers can break or change bytes they do not expect. Base64 sidesteps that by using characters every system treats the same way. The price is size: the encoded form is about one third longer than the original.

How to use this Base64 encoder and decoder

  • Pick the tab. "Encode to Base64" turns text into Base64; "Decode Base64" turns Base64 back into text.
  • To encode, type or paste into "Text to encode". The result updates with the Base64 and a Copy button.
  • Under More options, "Alphabet" switches between Standard (+ and /) and URL-safe (- and _). "End with = padding" adds or drops the = signs at the end.
  • "Line breaks" splits long output every 76 characters (email and MIME) or every 64 characters (PEM keys and certificates). Leave it on None for one long line.
  • "Write the text as" picks the character set used to turn your text into bytes. UTF-8 is the default and handles every language and emoji; choose UTF-16 little-endian for a PowerShell encoded command.
  • To decode, paste into "Base64 to decode". Spaces, line breaks, missing = signs, URL-safe characters and a data: prefix are all accepted.
  • If the text comes out with odd symbols, change "Read the bytes as" to another character set, or set "Show the result as" to Hex bytes to see every byte.

Nothing you type is sent to a server or saved in the page address, so a decoded token or private message does not end up in your browser history or a shared link.

Reading the result

When encoding, the big box is the Base64 text. Text size gives the number of bytes your text became, with the number of characters and the character set beside it. Base64 length counts the output characters without line breaks. When decoding, you see the decoded text (or hex bytes), the decoded size in bytes and the number of characters.

Bytes and characters differ for anything outside basic English. In UTF-8 an English letter is 1 byte, but an accented letter takes 2 bytes, many symbols take 3, and an emoji takes 4. Base64 works on bytes, so its length follows the byte count, not the letter count.

Worked example: encoding "Cat" by hand

Here is what the encoder does with the word Cat, step by step. The three letters are the bytes 67, 97 and 116. Together they make 24 bits, which split into four groups of 6 bits. Each group is a number from 0 to 63, and each number is one character from the table above.

"Cat" becomes Q2F0
StepWhat you get
LettersC, a, t
Byte values67, 97, 116
8 bits per byte01000011 01100001 01110100
Same bits in groups of 6010000 110110 000101 110100

So Cat encodes to Q2F0, 4 characters for 3 bytes. With fewer bytes in the last group, the encoder fills the gap with zero bits and adds = signs: "Ca" becomes Q2E= and a single "C" becomes Qw==. One = means the last group held 2 bytes; two mean it held 1 byte.

A longer word shows the same rule. Karachi is 7 bytes, which is two full groups of 3 plus 1 byte left over, so the output is 12 characters: S2FyYWNoaQ==. With the URL-safe alphabet and padding switched off it is S2FyYWNoaQ, 10 characters.

Character sets: UTF-8, UTF-16 and the rupee sign

Base64 never sees letters, only bytes, so the character set decides what gets encoded. Take the text "Price: ₨ 1,500", which is 14 characters and uses the rupee sign ₨. In UTF-8 the rupee sign takes 3 bytes, so the text is 16 bytes and the Base64 is UHJpY2U6IOKCqCAxLDUwMA== (24 characters). Written as UTF-16 little-endian, every character takes 2 bytes, so the same text is 28 bytes and 40 Base64 characters long.

Decoding has the reverse problem. The Base64 Y2Fm6Q== holds the 4 bytes of "café" written in the old Windows-1252 set. Read as UTF-8, the last byte is not valid and you see caf� with a warning. Set "Read the bytes as" to Windows-1252 and it reads café. When nothing looks right, the data may not be text at all; Hex bytes shows it exactly, for example 4B 61 72 61 63 68 69 for Karachi.

Where Base64 is used

  • Email attachments: MIME (RFC 2045) sends files as Base64 in lines of at most 76 characters, which is why that line length is an option here.
  • Keys and certificates: PEM files (RFC 7468) hold Base64 between BEGIN and END lines, wrapped at exactly 64 characters.
  • Data URLs: a small image or font can sit inside HTML or CSS as data:image/png;base64, followed by the Base64 (RFC 2397). Paste one here and the data: part is skipped.
  • Web tokens: JSON Web Tokens use URL-safe Base64 with the = padding left out (RFC 7515), so the three parts of a token can be decoded here to read their JSON.
  • Basic login headers: HTTP Basic authentication sends user:password in Base64 (RFC 7617). For example user:pass2026 becomes dXNlcjpwYXNzMjAyNg==, which anyone can decode, so it is only safe over HTTPS.

Common mistakes and how to avoid them

  • A hidden newline: plain echo adds a line break, so echo Karachi | base64 gives S2FyYWNoaQo= instead of S2FyYWNoaQ==. Use echo -n, or paste the exact text here.
  • Calling btoa on Unicode: in a browser, btoa throws an error on any character above code 255, such as ₨ or an emoji. Turn the text into UTF-8 bytes first.
  • A + turning into a space: standard Base64 placed in a web address can lose its + signs. Use the URL-safe alphabet, or URL-encode the value with our URL Encoder / Decoder.
  • Treating Base64 as a secret: it has no password and no key, so anyone can reverse it. Real encryption, with a proper key, is the only way to hide data.
  • Wrong character set: if decoded text shows Ã© or �, the bytes are fine but are being read in the wrong set; try another one before assuming the data is broken.

How it works

Base64 writes any data with just 64 safe characters (A-Z, a-z, 0-9, + and /), so it can travel through email, web addresses, JSON and other places that only take plain text. To encode, your text is first turned into bytes, using UTF-8 unless you choose another character set, and every 3 bytes become 4 Base64 characters; = signs fill up the last group. To decode, the 4-character groups are turned back into bytes and the bytes are read as text. Spaces and line breaks in pasted Base64 are ignored, URL-safe Base64 (with - and _) and missing = signs are understood, and a data: prefix is skipped. Everything happens in your browser.

The formula

  • 3 bytes = 24 bits = 4 groups of 6 bits; each 6-bit group (0-63) is one character
  • 0-25 = A-Z, 26-51 = a-z, 52-61 = 0-9, 62 = + (or -), 63 = / (or _)
  • Base64 length = 4 × ⌈bytes ÷ 3⌉ with padding (1 or 2 = at the end), or ⌈4 × bytes ÷ 3⌉ without

A worked example

"Hi!" is the bytes 72, 105, 33 = 01001000 01101001 00100001. Split into 6-bit groups: 010010 000110 100100 100001 = 18, 6, 36, 33 = S, G, k, h, so "Hi!" is SGkh. "café ☕" is 9 bytes in UTF-8 and becomes Y2Fmw6kg4piV.

Questions

What is Base64 encode and decode?

Encoding rewrites data with 64 plain characters (A-Z, a-z, 0-9, + and /) so it can pass through systems that only handle text. Decoding reverses it and gives back the exact original bytes. It is a format change, not a way to hide anything.

Is Base64 encryption?

No. Base64 only rewrites data with a small set of characters; anyone can decode it in a second, as this page shows. Never use it to hide passwords or private data. Use real encryption for that.

Can you decode Base64 without a key?

Yes, always. Base64 has no key at all, so any Base64 string can be decoded by anyone with a tool like this one. If something asks for a key to decode, it is encrypted data that was then written in Base64, and the key belongs to the encryption step.

How do I Base64 encode and decode in Python?

Import the base64 module, then call base64.b64encode on bytes and base64.b64decode on the Base64 string; both return bytes. Use .encode() to turn a Python string into UTF-8 bytes first and .decode() to turn the result back into a string. For web addresses use urlsafe_b64encode.

How do I decode Base64 on the Linux command line?

Pipe the text into base64 -d, for example echo S2FyYWNoaQ== | base64 -d, which prints Karachi. To encode, use echo -n so no line break is added. GNU base64 wraps output at 76 characters unless you add -w 0.

Why does my decoded text show odd characters such as � or Ã©?

The bytes were written in a different character set from the one used to read them, or the data is not text at all (an image or a zip file, for example). Under More options choose another "Read the bytes as" set, such as Windows-1252 for old Western files, or choose "Hex bytes" to see the raw bytes.

What is URL-safe Base64?

A variant that uses - and _ instead of + and /, because + and / have special meanings in web addresses and file names. It is often written without the = padding. JSON Web Tokens use it. This page decodes both kinds automatically; choose the alphabet under More options when encoding.

What do the = signs at the end of Base64 mean?

They are padding. Base64 works in groups of 3 bytes, and when the last group has only 2 bytes one = is added, and with 1 byte two are added. Many decoders, including this one, can work without them.

Why is the Base64 longer than my text?

Every 3 bytes become 4 characters, so Base64 is about 33% longer than the data. Letters outside English take 2 to 4 bytes each in UTF-8, so text in Urdu, Arabic or with emoji grows more.

Can I see a Base64 encode example?

The word Cat is the bytes 67, 97 and 116, which regroup into the 6-bit values 16, 54, 5 and 52, giving Q2F0. Karachi gives S2FyYWNoaQ== and a single coffee emoji gives 4piV. Type any of them into the encoder to see the same result.

Is my text sent anywhere?

No. The encoding and decoding run in your browser, and the text boxes are not copied into the page address, so a decoded secret does not end up in your history or in a shared link.
