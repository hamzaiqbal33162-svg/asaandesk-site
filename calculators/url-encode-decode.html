How it works

Web addresses may only contain a small set of characters, and some of them (& = ? / # and the space) have special jobs. Percent-encoding writes every other character as its UTF-8 bytes, each as % followed by two hex digits: a space is %20, é is %C3%A9. Choose what you are encoding: a value inside a link (the usual choice, the same as JavaScript's encodeURIComponent), form data as browsers send it (spaces become +), strict RFC 3986 (also encodes ! ' ( ) *), or a whole web address (keeps the : / ? # & = that separate its parts). Decoding turns the %-codes back into text and, if you tick it, + into spaces. Spaces at the start and end are left out unless you change that under More options.

The formula

  • Each character -> its UTF-8 bytes -> %XX for each byte (XX = the byte in hex, upper case)
  • space = %20 (or + in form data), & = %26, = = %3D, / = %2F, ? = %3F, % = %25
  • é = U+00E9 = bytes C3 A9 = %C3%A9; ☕ = U+2615 = E2 98 95 = %E2%98%95

A worked example

"a b&c=d/é?" as a value: a, b, c and d stay; the space is %20, & is %26, = is %3D, / is %2F, é is %C3%A9 and ? is %3F, so it becomes a%20b%26c%3Dd%2F%C3%A9%3F. As form data the space would be + instead.

Sources

  • RFC 3986: Uniform Resource Identifier, section 2.1 percent-encoding (IETF)
  • WHATWG URL Standard: application/x-www-form-urlencoded
  • MDN: encodeURIComponent()

Questions

Should a space be %20 or +?

%20 is right everywhere in a web address. The + for a space only means a space in form data and in the query part of some servers' links (after the ?). If you are not sure, use %20; when decoding form data, tick "Read + as a space".

Why are / and : encoded when I paste a whole link?

"A value in a link" encodes everything that could change the meaning of a link, which is right when the text is one value inside another link (for example a link passed in ?url=). To tidy up a complete address and keep its parts working, choose "A whole web address".

What does "not a complete code" mean?

Every % must be followed by two hex digits (0-9 and A-F). A lone % or a code cut short, such as %E0%A4%A, cannot be decoded. A real percent sign is written %25, so 50% becomes 50%25.

Does it work for Urdu, Arabic and emoji?

Yes. Characters are written as their UTF-8 bytes, the standard for web addresses: é becomes %C3%A9, ☕ becomes %E2%98%95, a letter of the Urdu or Arabic alphabet becomes two codes such as %D8%B3, and everything decodes back exactly.

Is my text sent anywhere?

No. Encoding and decoding run in your browser, and the text boxes are not copied into this page's address, so links with private tokens do not end up in your history.
